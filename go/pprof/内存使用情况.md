
采集内存使用情况
```shell
# 获取当前程序的内存使用情况
go tool pprof http://127.0.0.1:6060/debug/pprof/heap
```

执行上面这个命令后，会进入终端，在终端中通过命令分析内存使用情况

# top

**作用**： 查看内存占比最大的前10个函数，如果需要指定前N条数据，在top后面跟数字即可，例如`top8`展示前8条。

**示例**：

```shell
(pprof) top3 # 展示前3条内存消耗最大的函数
Showing nodes accounting for 14.14MB, 41.41% of 34.14MB total
Showing top 3 nodes out of 200
      flat  flat%   sum%        cum   cum%
    5.51MB 16.14% 16.14%     5.51MB 16.14%  runtime.allocm
    4.63MB 13.55% 29.69%     4.63MB 13.55%  github.com/dgraph-io/ristretto.newCmRow
       4MB 11.72% 41.41%        4MB 11.72%  github.com/dgraph-io/ristretto/z.(*Bloom).Size
```

|列名|含义|示例解析 (以第一行为例)|
|----|----|---------------------|
|flat|该函数自身分配的堆内存大小（不包含它调用的其他函数分配的内存）。|runtime.allocm 自身直接分配了 5.51MB|
|flat%|flat 内存占程序总分配内存 (34.14MB) 的百分比。|5.51 / 34.14 ≈ 16.14%，说明它自己分配的占到了总内存的16%。|
|sum%|从第一行到当前行的 flat% 的累计百分比。|前两行累计 16.14% + 13.55% = 29.69%。|
|cum|该函数累计分配的堆内存，包含它调用的所有子函数分配的内存。|runtime.allocm 累计分配了 5.51MB，说明它没有调用其他会分配内存的子函数。|
|cum%|cum 内存占总分配内存的百分比。|5.51 / 34.14 ≈ 16.14%。|


🔍 关键发现与解读
这份报告揭示了当前内存消耗的重点：

主要消耗点在运行时和内部数据结构：前3个函数分别是 runtime.allocm（Go运行时分配M结构）、ristretto.newCmRow（缓存库的内部结构）和 ristretto.z.Bloom.Size（布隆过滤器）。这三者合计已占总内存的 41.41%。

无需过度关注运行时：runtime.allocm 是 Go 调度器管理 M（系统线程）时产生的内存分配，通常不需要开发者干预。

缓存库占用较高：两个 ristretto（一个高性能缓存库）相关的函数占用了 8.63MB，约占总内存的25%，说明你的程序正在大量使用缓存。

# list <函数名>

**示例**:

# peek <函数名>

**作用**: 显示是哪些上层函数调用了<函数名>

**示例**：

```shell
(pprof) peek newCmRow
Showing nodes accounting for 34554.09kB, 100% of 34554.09kB total
----------------------------------------------------------+-------------
      flat  flat%   sum%        cum   cum%   calls calls% + context              
----------------------------------------------------------+-------------
                                         4737.10kB   100% |   github.com/dgraph-io/ristretto.newCmSketch (inline)
 4737.10kB 13.71% 13.71%  4737.10kB 13.71%                | github.com/dgraph-io/ristretto.newCmRow
```
