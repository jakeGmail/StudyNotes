# 使用

使用以下命令获取程序当前的协程堆栈
```shell
go tool pprof http://127.0.0.1:6060/debug/pprof/goroutine
```

# 终端命令

## top

**作用**: 采集当前状态下，程序的协程数量和状态

**使用示例**：

```shell
(pprof) top3
Showing nodes accounting for 167, 100% of 167 total
Showing top 3 nodes out of 172
      flat  flat%   sum%        cum   cum%
       165 98.80% 98.80%        165 98.80%  runtime.gopark
         1   0.6% 99.40%          1   0.6%  runtime.goroutineProfileWithLabels
         1   0.6%   100%          1   0.6%  runtime.notetsleepg
```

Goroutine Profile top 输出列含义

|列名|	含义|	示例解析 (以第一行为例)|
|----|------|--------------------------|
|flat|	处于该状态的 goroutine 数量。|	runtime.gopark 函数当前有 165 个 goroutine 正在其中。|
|flat%|	该状态的 goroutine 数量占总 goroutine 总数 (167) 的百分比。|	165 / 167 ≈ 98.80%，说明绝大多数 goroutine 都处于这个状态。|
|sum%|	从第一行到当前行的 flat% 的累计百分比。|	前两行累计 98.80% + 0.60% = 99.40%。|
|cum|	与 flat 含义相同，因为 goroutine profile 通常只关注当前状态，不涉及调用链累计。|	与 flat 一致，为 165。|
|cum%|	与 flat% 含义相同。|	与 flat% 一致，为 98.80%。|

这份报告揭示了 Goroutine 的整体运行状态：

绝大多数 Goroutine 处于空闲/等待状态：`runtime.gopark` 是 Go 运行时用来挂起 Goroutine 的函数。当 Goroutine 在等待某个事件（如 time.Sleep、channel 读写、sync.Mutex 锁等待）时，会调用 gopark 进入休眠状态，不占用 CPU。

总体 Goroutine 数量很低：总数仅 167 个，在 Go 程序中非常健康。

没有 Goroutine 泄漏的迹象：Goroutine 泄漏通常表现为数量持续增长，且大量 Goroutine 卡在 runtime.gopark 上无法退出。从当前 snapshot 看，数量稳定且很少。
